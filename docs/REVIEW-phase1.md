# 1단계 독립 보안 검토 기록

검토 대상: 0단계 검토 이후의 수정분(인증 흐름 재작성 등)과 1단계 백엔드(사용자·역할 관리, 부서 범위, 기업 선택).
검토자는 구현 과정을 보지 않은 별도 세션(Opus)이며, 발견 사항은 별도 DB에서 재현했다.
결론: 다른 기업 데이터에 접근하는 경로는 찾지 못했다. 기업 안에서의 권한 상승 1건이 재현됐다.

## 조치하지 않은 것

- **기업이 비활성화됐다가 다시 활성화되면**, 시스템 관리자의 이전 기업 선택이 새 감사 기록 없이 되살아난다.
  기업 비활성화 API를 만들 때 그 기업을 가리키는 선택을 함께 지운다(현재 그 API는 없다).
- **로그인·비밀번호 변경의 "검증하는 사이에 비밀번호가 바뀜" 검사**에는 테스트가 없다. 단계 사이에 끼어드는 장치가 없어
  결정적으로 재현할 수 없다. 코드 검토로만 확인했다.
- `tests/hardening.test.ts` 의 "잠기기 직전에 시작된 맞는 비밀번호 시도" 테스트는 실제 경쟁을 만들지 못한다(검토자 지적).
  같은 검사는 20개 동시 시도 테스트가 잡는다. 보호 대상 파일이라 이번에는 고치지 않았다.

## 확인하지 못한 것

- 실제 Supabase(Supavisor), 실제 프록시 헤더, 서버를 여러 대 띄웠을 때의 제한 동작.
- 이번 조치 이후의 코드는 독립 검토자가 다시 보지 않았다. 2단계 검토에 관리 기능을 다시 포함한다.
