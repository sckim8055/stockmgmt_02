# 6단계 검토 기록 (운영 구성, 5단계 수정분 재검토)

범위: `Dockerfile`, `deploy/**`, `scripts/set-role-limits.mjs`, `docs/OPERATIONS.md`, `tests-e2e/**`, 그리고 5단계 검토 뒤에 고친 코드
(재고 이력 쿼리, 0009 마이그레이션과 그 쿼리, 엑셀 읽기, 업로드 수신 제한, 입력 검증, 보안 헤더).

검토 방법: 코드를 쓰지 않은 독립 검토자(Opus)가 앱 역할(RLS 적용)로 20만~100만 건 규모에서 실행 계획과 시간을 재고,
이력 쪽 나눔을 2,000쪽 넘게 이전 쿼리와 대조하고, 백업 스크립트를 Docker 대역으로 실행하고, 변이 테스트 34건을 수행했다.
재현 테스트는 `tests/review6.test.ts` 에 있고 조치 뒤 모두 통과한다.

**이 환경에는 Docker 실행기가 없다.** Docker 구성과 윈도우 PowerShell 스크립트는 읽고 추론한 검토이며 실제 실행으로 확인하지 못했다.

## 결론

- 다른 기업의 데이터를 읽는 경로는 찾지 못했다. 이력 쪽 나눔은 정확했고, 0009 의 중복 방지와 인덱스는 의도대로 동작했다.
- **5단계에서 내가 넣은 조치 두 가지가 새 가용성 문제를 만들었다**(업로드 동시 수신 2건 제한, 업로드가 잡는 잠금을 기다리는 요청).
- 재고 이력은 여전히 조건에 따라 이력 전체를 읽었다.

## 고치지 않고 남긴 것

- **M3: 잠금 대기·쿼리 시간 초과(DB 가 끊은 경우)가 사용자에게 일반 500 으로 보인다.** 503 "잠시 후 다시"로 바꾸려면 보호 파일
  `src/lib/http/route.ts` 를 고쳐야 한다. 기업 잠금은 이제 2초 뒤 409 로 끝나므로 이 경로에 도달할 일은 줄었다.
- 재고 이력의 조건 검색은 최근 2만 건(기간 안) 밖을 보지 않는다. 오래된 이력을 조건으로 찾으려면 기간을 지정해야 한다.
- 같은 기업에서 엑셀 업로드가 도는 동안(2,000행이면 약 8~10초) 그 기업의 계정·역할·부서·기준 정보 변경은 2초 뒤 409 로 거절된다.
- 운영 이미지에 개발 의존성과 `src` 전체가 들어 있다(시스템 관리자 생성 스크립트를 같은 이미지로 실행하기 위해). 줄이려면 그 스크립트를 따로 빌드해야 한다.
- 상태 확인(healthcheck)은 DB 접속까지 보지 않는다. 로그인 없이 열리는 API 를 추가하려면 허용 목록 변경이 필요하다.
- 새 판을 올릴 때 접속이 잠시 끊긴다(무중단 배포 아님). 구조 변경을 되돌리는 스크립트는 없다(백업으로 복원).
- 변이 테스트에서 살아남았고 테스트가 없는 것: "오늘 계산했는가" 기록의 조회 기간, 자기 사번의 대소문자만 바꾸는 수정, CSP 헤더(브라우저 점검으로만 확인).
- CSP 는 인라인 스크립트를 허용하므로, 화면에 스크립트가 끼어드는 결함이 생기면 다른 곳으로의 이동(navigation)을 통한 유출까지는 막지 못한다.
- 이전 단계에서 남긴 항목은 그대로다.

## 확인하지 못한 것

- **Docker 로 실제 빌드·실행**: 이미지 빌드, 비루트 계정에서 `.next` 쓰기, 종료 신호, 재부팅 뒤 재기동.
- **윈도우 PowerShell 5.1 에서 `backup.ps1`**: 문자 인코딩, 작업 스케줄러에서의 종료 코드.
- 파이어폭스·사파리에서 `http://localhost` 로그인(크롬은 확인).
- Cloudflare Tunnel 뒤에서의 요청 버퍼링·Host 헤더.
- 실제 Microsoft Excel 이 저장한 파일.
- 이 문서의 조치 자체는 독립 검토를 다시 받지 않았다.
