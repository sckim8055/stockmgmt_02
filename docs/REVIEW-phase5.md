# 5단계 검토 기록 (대시보드, 이력, 3개 언어, 디자인)

범위: 대시보드·이력 API(`src/lib/reports`, `/api/dashboard`, `/api/history/**`), `PATCH /api/me`, 마이그레이션 0008,
3개 언어 계층(`src/app/i18n`), 디자인(`src/app/globals.css`), 그리고 4단계 검토 뒤에 고친 코드의 재검토.

검토 방법: 코드를 쓰지 않은 독립 검토자(Opus)가 기업당 자산 6만·이력 33만·알림 100만 건 규모의 자료에서
앱 역할(RLS 적용)로 실행 계획을 재고, openpyxl·LibreOffice 로 만든 실제 엑셀 파일을 읽혀 보고, 변이 테스트 56건을 수행했다.
재현 테스트는 `tests/review5.test.ts`, 엑셀 파일은 `tests/fixtures-review5/` 에 있고 조치 뒤 모두 통과한다.

## 이 단계에서 알게 된 것: RLS 와 인덱스

앱 역할에는 행 수준 보안(RLS)이 걸려 있다. 이 상태에서는 조건에 "누설 방지(leakproof)"가 아닌 함수·연산자
(`lower()`, `->>`, `?`, `ILIKE` 등)가 들어 있으면 PostgreSQL 이 그 조건을 **인덱스 조건으로 쓰지 못한다.**
표현식 인덱스가 있어도 그 기업의 행 전체(경우에 따라 테이블 전체)를 읽는다. 소유자 계정으로 실행 계획을 보면 드러나지 않는다.
조회 조건에 쓸 값은 저장된 열(생성 열)로 빼고 평범한 `=` 로 비교한다(0008, 0009).
**새 쿼리의 실행 계획은 앱 역할 + 기업 문맥에서 확인한다**(`tests/review5.test.ts` 의 `tenantSession` 참고).

## 결론

- 다른 기업의 데이터를 읽는 경로, SQL 주입 경로는 찾지 못했다. 약 1만 6천 건의 동시 혼합 처리에서 교착이 없었다.
- 가용성 문제가 다시 나왔다. 이번에는 새로 만든 재고 이력 목록이 원인이었다.
- 4단계 수정 중 하나(엑셀 속성 읽기)가 정상 파일을 거부하는 회귀를 만들었다.

## 테스트 보강

엑셀로 올린 재고의 한계 수량 판정(업로드 끝의 판정이 빠져도 알아채지 못했다), 대시보드의 카테고리·대여 수치의 부서 범위,
이력 검색의 LIKE 문자 처리와 끝 날짜 포함, 시리얼 중복의 대소문자, 서식만 있는 빈 행, 셀 안 줄바꿈.

## 고치지 않고 남긴 것

- **변이 테스트에서 살아남았고 아직 테스트가 없는 것**: 대시보드·이력의 날짜가 기업 시간대인지(UTC 로 바꿔도 통과), 알림 행 수 상한,
  보증 만료 30일 창, "오늘 했는가" 기록의 조회 기간, 한계 수량 잠금의 ID 순서, 모델 변경 시 이전 모델의 재판정,
  잘린 글자 목록 거부, 중복 속성 처리, 업로드 30초 제한.
- 드물게 맞는 검색어로 이력을 찾으면 맞는 행을 찾을 때까지 이력을 계속 읽는다. 감사 로그의 행위·대상 ID 조건은 인덱스를 쓰지 못한다(12만 건에서 27~144ms).
- 부서·카테고리·모델·역할·로그인 ID 의 중복 검사도 `lower()` 조건이다. 기업당 건수가 적어 그대로 뒀다.
- **CSP 는 인라인 스크립트·스타일을 허용한다**('unsafe-inline'). 화면이 인라인 스타일을 쓰고 Next.js 가 인라인 스크립트를 넣기 때문이다.
  더 엄격하게 하려면 nonce 방식으로 바꿔야 하고 모든 화면이 동적 렌더링이 된다.
- 감사 로그에는 접속 IP, 메일 수신 주소, 로그인 ID, 조정 사유(자유 입력)가 들어 있다. 볼 수 있는 사람은 기업 관리자와
  `history.audit:read` 를 받은 범위 제한 없는 계정이다(기본 역할에는 없다).
- 기업 전체 재고 이력에서, 부서 범위가 제한된 사용자는 자산이 자기 부서로 오기 전의 이력(이전 보유자·메모)도 본다(자산별 이력과 같은 기준).
- 이름 입력과 메일 제목은 C1 제어 문자·방향 전환 문자 등을 걸러내지 않는다(표시 혼동만 가능, 헤더 끼워 넣기는 불가).
- 모델의 카테고리 변경과 자산 처리가 정확히 겹치면 새 카테고리의 한계 수량이 판정을 한 번 놓칠 수 있다(재현하지 못한 추정).
- 서버가 내려주는 오류 메시지, 엑셀 양식의 열 이름과 오류 메시지는 한국어뿐이다.
- 대화상자가 키보드 초점을 가두지 않는다.
- 이전 단계에서 남긴 항목은 그대로다.

## 검토가 필요한 보호 파일 관련 사항 (미조치)

이전 기록과 같다: 정기 실행기용 `withSystem` 허용 목록, `guard.test.ts` 강화, `assertSafeRole`, `pool.on('error')`, 테이블 수를 세는 보호 테스트.
추가 제안: 앱 역할에 `statement_timeout` 을 주는 것(느린 쿼리 하나가 연결을 오래 붙잡지 못하게). 역할 설정이라 운영 구성에서 결정한다.

## 확인하지 못한 것

- 실제 Microsoft Excel 과 .NET 계열 도구가 저장한 파일(openpyxl·LibreOffice 로 대신했다).
- 실제 프록시 뒤에서의 업로드 본문 처리, Supabase, 여러 프로세스 배포.
- 이 문서의 조치 자체는 독립 검토를 다시 받지 않았다. 다음 단계 검토 범위에 포함한다.
- 화면 브라우저 테스트 스크립트는 저장소 밖(`/tmp/ui-smoke-theme/`)에 있다. 저장소에 넣어 자동화하는 일이 남아 있다.
